# Implementation Plan: CLI Quick Mode

**Branch**: `002-cli-quick-mode` | **Date**: 2026-06-20 | **Spec**: [specs/002-cli-quick-mode/spec.md](specs/002-cli-quick-mode/spec.md)
**Input**: Feature specification from `specs/002-cli-quick-mode/spec.md`

## Summary

FR-002 implements the CLI quick mode for ad-hoc HTTP load testing. The user runs `htload <url> [flags]` without writing a YAML scenario file. Quick mode compiles CLI flags internally into a single-phase `engine.Scenario` with one Step, then executes it via the existing `engine.Runner`. After execution, threshold assertions (`--fail-if-p99`, `--fail-if-rate`) evaluate aggregate results and determine the exit code.

**Technical approach**: Extract the existing cobra flag boilerplate from `cmd/htload/main.go` into a separate `cmd/htload/root.go` file (cobra-only), leaving `cmd/htload/main.go` as pure business logic that compiles flags to a `Scenario`, invokes the `Runner`, and evaluates thresholds. No new external dependencies; Cobra is already present in `go.mod`.

### Architecture Flow

```
User Input ──► root.go (cobra flag parse, URL validation)
                   │
                   ▼
              main.go Run()
                   │
         ┌─────────┴──────────┐
         ▼                    ▼
  compileFlags()       evaluateThresholds()
  (build Scenario)     (p99, success rate)
         │                    │
         ▼                    ▼
  engine.Runner ◄────── results slice
  │
  ▼
pkg/http/driver.go
```

**Compilation**: Quick mode flags are compiled into a single `Phase` with a `Constant` rate profile. The Step contains the parsed URL (base URL split from path), headers, method, body source, and a default `{Status: 200}` assertion.

**Threshold Evaluation**: After `Runner.Run()` returns, the results slice is scanned to compute:
- Total request count
- Success count and success rate
- p99 latency (via latency distribution aggregation from `Result.Latency`)

These aggregates are compared against `--fail-if-p99` and `--fail-if-rate` thresholds. A breach returns an error that propagates as exit code 1.

**Exit Code Determinism**:
- `0` — All assertions passed and no thresholds breached.
- `1` — Any step assertion failed, threshold breached, or runner error (e.g., connection refused).
- `2` — Invalid arguments: missing URL, malformed URL scheme, unreadable body file, invalid flags (e.g., workers ≤ 0).

## Key Implementation Points (Architecture Level)

1. **Two-File Command Split**: The existing `cmd/htload/main.go` contains both cobra setup (`rootCmd`, `init()`, `main()`) and business logic (`runQuick`, `execute`, `percentile`). This violates Constitution II. The refactor separates concerns so that `root.go` owns all cobra interaction and `main.go` owns the `Run()` orchestration.

2. **Flag Compilation Logic**: `Run()` receives a populated flag struct (or direct values) and constructs an `engine.Scenario`. The algorithm handles:
   - URL parsing (`url.Parse`) to split `BaseURL` (scheme + host) from `Path` (path + raw query)
   - Header parsing (split on first colon, trim whitespace)
   - Body source resolution (inline string vs. `@file` prefix)
   - Count-vs-duration precedence (count wins; if neither, default duration 30s)

3. **Threshold Evaluation**: Performed after `Runner.Run()` returns, not inside the runner. This keeps the engine protocol-agnostic and places CI-gate logic in the CLI layer. The evaluator computes success rate and p99 from the `[]Result` slice. If a threshold is configured (non-zero) and breached, `Run()` returns an error that `root.go` translates to exit code 1.

4. **Testing Strategy**:
   - **Unit tests** (`root_test.go`): Flag parsing edge cases (zero workers, negative duration, malformed headers).
   - **Integration tests** (`main_test.go`): Spawn an `httptest.Server`, invoke `Run()` directly or via `exec.Command`, assert exit codes, request counts, and threshold behavior.
   - **Coverage target**: ≥60% for `cmd/htload/`.

5. **Version Flag**: `--version` prints a build-time version string. It is registered as a `PersistentFlag` on the root command and short-circuits before `Run()`. The version value comes from a `var Version = "dev"` injected at link time or read from module metadata.

## Risk Mitigation

| Risk | Mitigation |
|---|---|
| Refactoring existing `main.go` breaks scenario mode (`-f`) | Scenario path is preserved unchanged in `Run()`. The `root.go` wiring routes `--file` to the same `runScenario()` call. |
| Threshold evaluation naïvely sorts all latencies (O(n log n)) | Use the engine's existing latency aggregation if available; otherwise document that p99 computation uses `sort` with a TODO for HDR histogram (Constitution: Result Integrity §). |
| Exit code 2 vs 1 ambiguity | Document in contract: parse/validation errors → 2; runtime/test failures → 1. |
